# 요강 분석 (rubric-parser)

공모전 준비의 모든 단계는 이 결과물(rubric.json)을 기준으로 움직인다. 정확성이 가장 중요하다.

## 절차

1. **폴더 준비** – `contests/<YYYY>-<짧은이름>/`과 `00_공고/`가 없으면 만든다.
2. **원문 확보**
   - URL이면 WebFetch로 읽는다. 내용이 비어 있거나 JS로 렌더링되는 사이트면 Playwright MCP로 연다.
   - 첨부 요강(PDF 등)은 `00_공고/`에 있으면 Read로 읽는다. 없으면 다운로드 링크를 알려주고 넣어 달라고 한다.
   - PDF가 길거나 스캔본·표가 많으면 `pdf` 스킬(document-skills)을 써서 텍스트·표를 추출한다.
   - **HWP·HWPX**: `hwp` MCP(hwp-mcp)로 읽는다. 한글 프로그램 없이 `.hwp`와 `.hwpx` 둘 다 읽을 수 있다.
     - 본문은 텍스트 읽기 도구로, **심사기준·배점 표는 표 읽기 도구로 따로 추출**한다(본문 텍스트에서 표를 추측해 재구성하지 않는다).
     - 사용자에게 PDF 변환을 요청하는 것은 hwp MCP가 연결되지 않았거나 읽기에 실패했을 때만 한다.
3. **추출** – 아래 스키마대로 채운다. 원문에 없는 항목은 지어내지 말고 `null`로 두고 `missing`에 적는다.
4. **배점이 없는 경우** – 심사기준만 있고 배점이 없으면 항목을 균등 배분하고 `"weight_source": "추정"`으로 표시한다.
5. **위험 신호 점검** – AI 사용 금지/표기 의무, 팀 인원 제한, 중복 응모 금지, 수상작 저작권 귀속, 지정 양식·파일 형식(HWP 필수 등)을 `warnings`에 적는다.
6. **저장 후 보고** – `rubric.json`에 저장하고, 사용자에게 5줄 이내로 알린다:
   마감일(D-day), 제출물, 배점이 가장 큰 심사항목 2개, 경고 사항, 원문에서 못 찾은 항목.

## rubric.json 스키마

```json
{
  "title": "공모전 정식 명칭",
  "host": "주최/주관",
  "url": "공고 URL",
  "field": "IT|아이디어|공공데이터|디자인|영상|글쓰기|기타",
  "theme": "공모 주제 (원문 요약)",
  "eligibility": "참가 자격 (대학생, 팀 인원 등)",
  "schedule": {
    "apply_start": "YYYY-MM-DD",
    "deadline": "YYYY-MM-DD HH:MM",
    "result": "YYYY-MM-DD",
    "other": ["예선 발표 YYYY-MM-DD"]
  },
  "deliverables": [
    {"name": "기획서", "format": "PDF", "limit": "10페이지 이내", "template": "지정 양식 있음/없음"}
  ],
  "criteria": [
    {"name": "창의성", "weight": 30, "description": "원문 설명", "weight_source": "원문|추정"}
  ],
  "ai_policy": "허용|금지|표기 필요|언급 없음 (원문 근거 문장 요약)",
  "prizes": "시상 내역 요약",
  "warnings": ["수상작 저작권 주최측 귀속", "중복 응모 금지"],
  "missing": ["원문에서 찾지 못한 항목"]
}
```

## 주의

- 날짜는 항상 `YYYY-MM-DD`. "11월 말"처럼 모호하면 원문 그대로 적고 `missing`에 추가한다.
- 배점 합계가 100이 아니면 원문 그대로 두고 `warnings`에 표시한다.
- 오늘 날짜 기준으로 D-day를 계산한다. 마감이 이미 지났으면 가장 먼저 알린다.
